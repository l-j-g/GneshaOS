# GneshaOS parameters and preferences

GneshaOS separates stable machine configuration from the values you are
likely to tune while using the desktop:

- `system-parameters.nix` contains stable account, machine, hardware, and
  service-path values.
- `home/variables.nix` contains editable Home Manager preferences such as the
  theme, display scale, window gaps, fonts, and idle behavior.
- `hosts/<host>/system-parameters.nix` may override stable values for one host.
- `hosts/<host>/hardware-configuration.nix` is generated by
  `nixos-generate-config` and must not be hand-edited.

This document describes both files and how the system and Home Manager layers
fit together.

## Quickstart

For an existing NixOS machine:

```sh
git clone https://github.com/l-j-g/GneshaOS.git
sudo cp -r GneshaOS /etc/nixos
cd /etc/nixos

# Copy and edit stable machine/account values.
cp system-parameters.example.nix system-parameters.nix

# Edit desktop preferences directly.
${EDITOR:-vi} home/variables.nix

# Build the system layer, then activate Home Manager separately.
sudo nixos-rebuild switch --flake .#<host-directory-name>
nh home switch . -c <user>@<host-directory-name>
```

At minimum, set `userSettings.userName` and `userSettings.homeDirectory` in
`system-parameters.nix`. Set your Git identity, theme, scaling, and font sizes
in `home/variables.nix`.

## How it works

- `flake.nix` discovers each real directory under `hosts/` and emits one
  `nixosConfigurations.<directory-name>` plus one
  `homeConfigurations.<user>@<directory-name>` output. Directories beginning
  with `_` are excluded, so `hosts/_template/` remains copyable.
- The root system-parameter file provides shared stable values. If it is
  missing, the flake falls back to `system-parameters.example.nix`.
- A host-local `system-parameters.nix` is recursively merged over the root
  values. The discovered host directory name is authoritative for the flake
  output and replaces `systemSettings.hostName`.
- `home/default.nix` imports `home/variables.nix` and makes its values
  available to every Home Manager module.

## Stable system parameters

These values live in `system-parameters.nix` and generally change only when
the machine, account, or installation changes.

| Variable | Description | Example | Used by |
| --- | --- | --- | --- |
| `systemSettings.hostName` | Reference hostname. The host directory name is authoritative for flake outputs. | `"cf-fv1"` | `flake.nix`, NixOS services |
| `systemSettings.flakePath` | Absolute path of this flake on the machine. | `"/etc/nixos"` | shell and Sway workflow helpers |
| `systemSettings.timeZone` | IANA timezone for the NixOS system. | `"Australia/Sydney"` | NixOS system services |
| `systemSettings.latitude` / `longitude` | Geographic coordinates for wlsunset. South and west are negative. | `-33.87` / `151.21` | Sway startup |
| `systemSettings.displayWidth` / `displayHeight` | Native panel dimensions in pixels. | `2160` / `1440` | wallpaper sizing/documentation |
| `systemSettings.keyboardLayout` | XKB keyboard layout. | `"us"` | Sway input |
| `systemSettings.keyboardOptions` | XKB keyboard option remaps. | `"ctrl:nocaps"` | Sway input |
| `systemSettings.backlightDevice` | Machine-specific backlight device name. | `"intel_backlight"` | Waybar, SwayOSD, wluma |
| `systemSettings.alsSensorPath` | Machine-specific ambient-light sensor path. | `"/sys/bus/iio/devices/..."` | hardware documentation |
| `systemSettings.arrComposePath` | Absolute path to the self-hosted media stack compose file. | `"/home/lg/src/arr/docker-compose.yml"` | media shutdown service |
| `userSettings.userName` | POSIX login name. Must match the host's declared user. | `"lg"` | NixOS and Home Manager |
| `userSettings.homeDirectory` | User home directory and `@home` volume location. | `"/home/lg"` | Home Manager |

## Editable Home Manager preferences

These values live in `home/variables.nix`. Each setting is also documented
inline in that file so it remains easy to edit without searching the modules.

| Variable | Description | Example | Used by |
| --- | --- | --- | --- |
| `themeName` | Base16 theme. Use `"matrix-green"` or a scheme exposed by nix-colors. | `"ayu-dark"` | GTK 3/4, Dolphin/Qt, desktop palette, theme picker |
| `browserDefaultZoom` | Default webpage zoom factor; `1.5` means 150%. Saved per-site zoom and browser UI scale remain independent. | `1.5` | Firefox and LibreWolf |
| `gitUserName` | Name written into commits made with the configured Git client. | `"lg"` | Git |
| `gitUserEmail` | Email written into commits made with the configured Git client. | `"lg@lgreve.com"` | Git |
| `terminal` | Terminal command used by Sway, rofi, and Waybar. | `"kitty"` | terminal integrations |
| `displayScale` | Sway output scale. Use `"1"` for 100%, `"2"` for 200%, or a fractional value. | `"2"` | Sway and scale helper |
| `gapsInner` / `gapsOuter` | Inner and outer Sway window gaps, in pixels. | `5` | Sway |
| `terminalFontFamily` | Fixed-width TTF family used by Kitty. | `"Terminess Nerd Font Mono"` | Kitty |
| `stackedViewFontSize` | Sway stacked/tabbed title size, in points. | `14` | Sway |
| `terminalFontSize` | Shared terminal/UI font size, in points. | `16` | Kitty, Foot, Waybar, rofi, mako |
| `screenshotDir` | Directory where grimshot saves screenshots. `~` is expanded. | `"~/Pictures/Screenshots"` | Sway |
| `screenshotUploadUrl` | 0x0-compatible endpoint for screenshot uploads. | `"https://x0.at/"` | Sway bindings |
| `idleDimSec` | Seconds before the display dims. | `240` | swayidle |
| `idleDimPercent` | Brightness percentage used during idle dimming. | `10` | swayidle |
| `idleOffSec` | Seconds before the display powers off. | `600` | swayidle |
| `idleSuspendSec` | Seconds before battery-only suspend. | `900` | swayidle |
| `autoBrightness` | Whether wluma manages ambient brightness automatically. | `true` | wluma |

## Applying changes

1. Edit `system-parameters.nix` for account, host, hardware, timezone, and
   service-path changes.
2. Edit `home/variables.nix` for theme, scale, gaps, fonts, screenshots, idle
   behavior, and Git identity.
3. Use `nixos-rebuild build --flake .#<host-directory-name>` to validate system
   changes without activating them.
4. Use `nh home switch . -c <user>@<host-directory-name>` to activate Home
   Manager changes.

The bundled `rebuild` helper can activate both layers; `home-rebuild` is the
faster user-only path. The theme picker updates `home/variables.nix` and starts
the Home Manager activation in the background.

## Notes

- Keep `system-parameters.nix` and `system-parameters.example.nix` tracked;
  Git flakes do not include ignored or untracked files.
- `displayScale` is a string, for example `"1"`, `"1.5"`, or `"2"`.
- Check hardware names with `brightnessctl -l` and by inspecting
  `/sys/bus/iio/devices/` on the target machine.
- Never put passwords, tokens, private keys, or other machine secrets in
  either parameter file.

### GTK, Dolphin, and browser settings

GTK 3 uses `adw-gtk3` with Base16 named colors. GTK 4/libadwaita applications
receive matching CSS variables; their widget layout remains native. The GTK
light/dark preference follows the palette's background and foreground.
Dolphin uses the KDE Qt platform plugin, Breeze widgets, and the generated
`GneshaBase16` color scheme. The palette is also written directly to
`kdeglobals` so applications can read its color groups under Sway.

After applying Home Manager, log out and back in so Sway, launchers, and
D-Bus-activated applications inherit the new Qt environment. Reopen GTK apps
and Dolphin to load their updated stylesheets and settings.

Firefox and LibreWolf apply `browserDefaultZoom` after the selected profile
initializes. Fully quit the browser before relaunching; opening another window
of an existing process does not reload AutoConfig. Existing profiles, bookmarks,
and per-site zoom choices are preserved. The default zoom affects web pages,
not browser toolbar size. A site's saved zoom takes precedence; use Ctrl+0 to
reset that site to the default. Profile paths match this installation's XDG
locations (`~/.config/mozilla/firefox` and `~/.config/librewolf/librewolf`).

The zoom script requires privileged access to Firefox's content-preference
service, so its package enables unsandboxed AutoConfig for the store-managed
script. The web-content sandbox remains enabled. Ordinary `user.js` preferences
cannot set this database-backed default zoom.

References: [adw-gtk3 customization](https://github.com/lassekongo83/adw-gtk3#customization),
[libadwaita CSS variables](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/css-variables.html),
and [Firefox AutoConfig sandbox behavior](https://www.mozilla.org/en-US/firefox/62.0/releasenotes/).
